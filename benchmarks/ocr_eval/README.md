# OCR benchmark: EasyOCR vs. Pix2Text

Scores each OCR model on photographed math problems using the measures from Research Update #2:
error-free rate (the main measure), character and word error rate, critical errors by type, time per
photo, and energy per photo.

## 1. Take the photos (real photos only)

```bash
.venv/bin/python benchmarks/ocr_eval/build_problems.py   # pick 20 GSM8K + 10 MATH (seed 2026) -> dataset/problems.csv
.venv/bin/python benchmarks/ocr_eval/make_sheets.py      # -> dataset/sheets.html, one problem per page
open dataset/sheets.html
```

Photograph every problem in sheet order with your phone. Delete bad shots on the phone, then AirDrop
each set into its own folder.

| Photo type | How |
|---|---|
| **screen** | Full-screen the sheet (⌃⌘F), photograph the laptop screen, press → for the next problem. The tab title shows "Problem n / 30". |
| **printed** | File → Print (one problem per page). Photograph each sheet alone on a dark surface, so text from the sheet underneath doesn't show through. Hold the phone upright. |
| **handwritten** | Copy problems by hand in sheet order; any number from the start (use `--partial`). |

### Rendered images (no photos needed)

```bash
.venv/bin/python benchmarks/ocr_eval/render_pages.py     # -> photos/rendered/ and photos/rendered_blur/
```

Each problem is typeset exactly as on the photo sheet and screenshotted by headless Chrome; a
blurred copy (Gaussian, radius 2) is made from it. These are rendered from the text, **not
generated by an AI image model**, and are reported separately from real photos.

## 2. Import, run, score, graph

```bash
.venv/bin/python benchmarks/ocr_eval/import_photos.py --type screen  --from ~/Downloads/screen
.venv/bin/python benchmarks/ocr_eval/import_photos.py --type printed --from ~/Downloads/printed
.venv/bin/python benchmarks/ocr_eval/import_photos.py --type handwritten --from ~/Downloads/hw --partial
.venv/bin/python benchmarks/ocr_eval/run_ocr.py          # both models -> benchmarks/results/readings.jsonl
.venv/bin/python benchmarks/ocr_eval/score.py            # -> scored.csv, summary.json, hand_check.csv
.venv/bin/python benchmarks/ocr_eval/plots.py            # -> benchmarks/figures/*.png
.venv/bin/python benchmarks/ocr_eval/energy.py           # needs your password (powermetrics)
```

- `import_photos.py` matches photos to problems by the time they were taken and converts HEIC
  to JPEG. Open the contact sheet it writes (`dataset/photos/<type>_contact.jpg`) to check that
  each photo has the right label.
- `run_ocr.py --resume` continues an interrupted run.
- Photos are turned upright from their EXIF tag before OCR.
- Every line the model reads is scored (`--conf 0`).
- The first read of each model is a warm-up and isn't timed.

`problems.csv` columns: `problem_id`, `source` (`gsm8k`/`math`), `format` (`plain`: `$` is dollars;
`latex`: `$..$` is math), `reference` (the correct text).

## 3. Check the script by hand

`score.py` writes `hand_check.csv`, a random sample of 30 readings. Fill in `manual_critical` with
your own count and run `score.py` again. It prints how often the script agrees with you.

## How a critical error is counted

[`metrics.py`](metrics.py) converts both texts to one plain form (`\frac{3}{4}` → `3/4`,
`\sqrt{x}` → `√x`, `\pi` → `π`, `\times` → `×`). It then compares the numbers and math symbols in
each as unordered lists:

| Category | Tokens |
|---|---|
| number | `16`, `1000` |
| decimal | `3.00`, `0.5` |
| operator | `+ - × ÷ = < > ≤ ≥ ≠ ±` (not hyphens in words like "two-thirds") |
| frac/pow/root | `/ ^ √ π` |
| unit/currency | `$ % ° ¢ € £` |

Each category counts the larger of (tokens missing, tokens added), so `$3.00` read as `53.00` is
2 errors: a changed decimal number and a lost `$`. Spelling, punctuation and word order don't count.
Word order still raises CER.
